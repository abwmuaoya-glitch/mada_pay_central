# مدى باي المركزي — الإصدار التأسيسي 1.1

مشروع Flutter واحد يستهدف Android والويب بنفس الثيم والشاشات. الواجهة عربية RTL، بألوان كحلي `#0A1931` وذهبي `#D4AF37` وذهبي فاتح `#E8C765`، وشعار ذهبي وأزرار Material 3 مرتفعة الظلال وانتقالات متحركة.

## ما يتضمنه

- توجيه الحساب النشط تلقائياً: العميل إلى تبويبات الخدمات والعمليات والإعدادات ومساعد AI، والحساب الإداري إلى لوحة الإدارة.
- بوابة إدارة تتضمن لوحة التحكم، بوابات عدن وصنعاء، العمليات، ربط API، مزودي الدفع، مزودي الخدمات، كتالوج الخدمات، محرر روابط المستودع، مساعد AI، سجل التدقيق، والإعدادات.
- إعدادات المستخدم: تفضيل المصادقة الحيوية على الأجهزة المدعومة، تغيير كلمة المرور، طلب تغيير رقم الهاتف، عرض معرّف الجهاز، المظهر، وتسجيل الخروج. تتطلب حسابات العملاء اعتماد الجهاز قبل الوصول للخدمات، ويمكن للمالك اعتماد الجهاز من تبويب «العملاء والأجهزة» عبر إجراء SQL آمن محدود الصلاحية.
- روابط إلى مستودع GitHub وإجراءات البناء وإعدادات الاستضافة. لا يخزن التطبيق رمز وصول GitHub ولا يعدّل ملفات المستودع مباشرة.
- واجهة مساعد AI جاهزة بصرياً، لكن لا يوجد مزود ذكاء اصطناعي مربوط حتى الآن. لا تضع مفتاح AI في تطبيق الهاتف أو الويب؛ أضف تكاملاً خادمياً عند اختيار المزود.
- ملف ترحيل SQL إضافي يضيف جداول التكاملات والبوابات ومزودي الدفع والخدمات وسجل التدقيق. لا يعيد إنشاء `profiles` أو `user_roles` أو `transactions`.
- نفس مشروع Flutter يُبنى كتطبيق Android وكتطبيق ويب، ليبقى الشكل والسلوك متقاربين.

## إصدارات الأدوات والمكتبات المثبتة

- Flutter SDK: `3.24.5` عبر GitHub Actions.
- Dart SDK range: `>=3.5.0 <4.0.0`.
- `supabase_flutter`: `2.8.0`
- `google_fonts`: `6.2.1`
- `fl_chart`: `0.70.2`
- `url_launcher`: `6.3.1`
- `shared_preferences`: `2.3.2`
- `local_auth`: `2.3.0`
- `flutter_lints`: `4.0.0`

الإصدارات المباشرة محددة بأرقام ثابتة بدلاً من `^`. ينشئ أول بناء ناجح `pubspec.lock`، ويُرفع كأثر باسم `mada-pay-dependency-lock`. نزّل هذا الملف وأضفه إلى المستودع لتثبيت إصدارات التبعيات غير المباشرة أيضاً؛ لا يمكن ضمان ثبات كل التبعيات غير المباشرة قبل إنشاء ملف القفل وحفظه.

## استخدام قاعدة بيانات مدى باي الموجودة

1. لا تنشئ مشروع Supabase جديداً لمجرد تشغيل هذا المشروع.
2. راجع مخطط قاعدة البيانات الحالية، خاصة `public.user_roles` و`public.registration_requests` و`public.transactions`.
3. راجع ثم نفّذ `supabase/migrations/202610130001_mada_central.sql` في بيئة تطوير أولاً. الدالة الأمنية تفترض أن `user_roles` يحتوي على `user_id` و`role`؛ عدّلها إذا كان المخطط الفعلي مختلفاً.
4. أضف `SUPABASE_URL` و`SUPABASE_KEY` إلى GitHub Actions Secrets. استخدم مفتاح العميل العام/anon أو publishable فقط؛ لا تضع `service_role` في التطبيق أو الويب.
5. تأكد من سياسات RLS الحالية على الجداول الأساسية. نجاح تسجيل الدخول لا يعني وحده السماح بقراءة أو تعديل بيانات أي مستخدم.

## بناء APK والويب

- افتح GitHub → Actions → `Build Mada Pay Android and Web` → Run workflow.
- سيظهر أثر `mada-pay-central-apk` و`mada-pay-central-website` و`mada-pay-dependency-lock` بعد نجاح البناء.

## الاستضافة المجانية

تم تجهيز `deploy-website.yml` للنشر على Cloudflare Pages، وهو يوفر خطة مجانية مناسبة لموقع تجاري تعريفي/تطبيقي ضمن حدود الخطة. لإنشاء الرابط الفعلي:

1. أنشئ حساباً في Cloudflare، ثم أنشئ API Token بصلاحيات Pages المناسبة.
2. أضف في إعدادات المستودع → Settings → Secrets and variables → Actions السرّين `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID`، بالإضافة إلى أسرار Supabase.
3. شغّل GitHub Actions → `Deploy Mada Pay Website to Cloudflare Pages`.
4. بعد النشر، أضف عنوان الموقع إلى Supabase Auth → URL Configuration إذا كانت إعادة التوجيه/تأكيد البريد مستخدمة.
5. بعد نجاح أول نشر، يكون الرابط الافتراضي: `https://mada-pay-central.pages.dev` (إذا كان اسم المشروع متاحاً). يمكن ربط نطاق خاص لاحقاً من Cloudflare.

لم يتم إنشاء حساب Cloudflare أو إصدار الرابط الحي من هذه الجلسة؛ يحتاج ذلك إلى حسابك وتفويضك. لا تضع أسرار الاستضافة في ملفات الكود.

## ما لم يُفعّل بعد

- تنفيذ تحويلات أو مدفوعات حقيقية، أو الاتصال المباشر بالبنوك اليمنية والعربية.
- مزود AI فعلي.
- تحرير ملفات GitHub من داخل التطبيق؛ التبويب يفتح أدوات GitHub الآمنة حالياً.
- توثيق هوية KYC كامل ورفع مستندات آمن.
- التسجيل الجديد عبر الويب يضيف بيانات الحساب الأساسية؛ وقد يتطلب تأكيد البريد حسب إعدادات Supabase، كما يتطلب اعتماد الجهاز قبل دخول العميل.

تُحفظ طلبات العميل كطلبات مراجعة فقط. لا تُعرض على أنها حوالة منفذة. قبل تفعيل أي مزود مالي، يلزم عقد تكامل رسمي، موافقة المزود، واجهة API موثقة، تسوية ومطابقة، وسياسات أمان وامتثال واختبارات Sandbox. لم يتم التحقق من توافق أي بنك بعينه لأن وثائق API وبيئة الاختبار لكل بنك/محفظة لم تُقدَّم بعد؛ لا يدّعي المشروع وجود ربط مصرفي جاهز.
